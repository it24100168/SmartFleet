# Proposed assessment deployment using Azure for Students

**Status: accounts ready, resources not yet verified.** On 5 October the team reported that both Azure for Students and a fresh Neon Free project dashboards are accessible. Microsoft lists [US$100 credit usable within 12 months](https://azure.microsoft.com/en-us/pricing/offers/ms-azr-0170p) for eligible students, with no credit card needed at sign-up. Verify the active subscription is **Azure for Students**, not the restricted Starter offer, and check remaining credit, region and quotas in the Azure portal. Do not assume the full US$100 remains available. Follow the [deployment runbook](AZURE-NEON-DEPLOY.md) for exact settings and checks.

## Recommended small assessment topology

| Component | Proposed service | Why / limit |
| --- | --- | --- |
| React | [Azure Static Web Apps Free](https://learn.microsoft.com/en-us/azure/static-web-apps/plans) | Supports React/GitHub deployment and HTTPS at no plan charge within Free quotas. Configure SPA route fallback and build-time `VITE_API_BASE_URL`. |
| ASP.NET Core API and background mission worker | Azure App Service **Basic B1**, paid from available student credit after checking the portal estimate | The API's `MissionSimulator` must keep running to advance orders. Azure says an app without Always On can unload after about 20 minutes, and [Always On is available in Basic and above](https://learn.microsoft.com/en-us/azure/app-service/webjobs-create). Use one instance, enable Always On, set a cost budget and watch credit consumption. No fixed price is claimed because region/offer rates vary. |
| PostgreSQL | A **new** [Neon Free](https://neon.com/blog/neon-free-plan-1-gb-per-project) project | As of 2 October 2026, Neon states 1 GB/project and 100 CU-hours/project/month. This avoids spending Azure credit on a second always-on resource. Treat it as an assessment-sized database and test cold-start behavior. Do not reuse any previously exposed Neon credential; rotate it and keep the new connection string only in App Service settings. |
| Android | Final Flutter APK | Build with the **public HTTPS API** URL, then install on a clean emulator/device and record the cross-client approval scenario. |
| Weather | Server-side Open-Meteo by default, or existing OpenWeather provider when configured | Open-Meteo is keyless for this non-commercial educational use; it uses fixed Colombo coordinates and does not transmit user or mission IDs. Validate a real response and capture safe failure/rate-limit evidence. If choosing OpenWeather, its key stays private in App Service. |

An all-Azure alternative uses Azure Database for PostgreSQL Flexible Server instead of Neon. Its availability and cost for a Student subscription depend on the exact offer, region and quota; Microsoft's [capacity guidance](https://learn.microsoft.com/en-us/azure/postgresql/troubleshoot/how-to-resolve-capacity-errors) notes restricted regions for student/program subscriptions. Check the portal's estimated cost before creating it. Azure App Service Free F1 may be useful for a quick smoke test, but its [daily CPU quota](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/azure-subscription-service-limits) and lack of Always On make it a weak choice for the required continuously progressing fleet and evaluator-access period.

## Code and account gates before deployment

1. Production-safe [privileged account provisioning](../backend/Services/PrivilegedAccountProvisioner.cs) is now in source and tested. On the first deployment, set `Provisioning__Supervisor__Name`, `__Email`, `__Password` and the equivalent `Provisioning__Technician__...` private App Service settings. Passwords must be at least 12 characters. The bootstrap hashes them, creates accounts only if absent, and refuses to change an existing account's role; remove the plaintext password settings after first successful start. Public self-registration stays Operator-only. The local `DemoSeeder` uses known demo account names and must not be used as cloud production provisioning.
2. The deployed API can now expose Swagger only when `Swagger__Enabled=true` is explicitly set; endpoints retain their role checks. Verify `GET /api/health` and `/swagger` through HTTPS.
3. Set `ASPNETCORE_ENVIRONMENT=Production`, `Database__Provider=PostgreSQL`, `ConnectionStrings__DefaultConnection`, `Database__ApplyMigrations=true` for the first controlled startup, a strong private `JwtSettings__Secret`, restricted `Cors__AllowedOrigins__0`, and `WeatherSettings__Provider=OpenMeteo` as App Service configuration. Confirm whether uploaded breakdown photos remain available after restart/redeploy; use persistent storage or document the tested limit.
4. Deploy the API, apply migrations and test login/roles/workflow against the new database. Deploy React with the API's public URL, then build the APK with that same API URL. Recheck CORS, HTTPS and upload paths from an incognito browser and native Android.
5. Set a budget alert; record actual service names, URLs, cost estimate, health/Swagger result, migration/test output, and the final APK install evidence. Keep all evaluator links available through the specification's 21 October 2026 access date.

No resource, cost or live URL is claimed by this plan until it is verified. The team controls the hosting accounts and will enter credentials directly into their private host settings.
